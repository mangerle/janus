核心优势

切换系统，不该在开机时赌手速

双系统用户的日常是：重启 → 盯紧屏幕 → 狂按 F8。Janus 把这件事变成托盘里的一次点击——固件层面的 BootNext 机制让下一次启动直接落点在你选的系统上。

01

一次点击 = 切换 + 重启

托盘菜单写入 BootNext 并立即重启；polkit 密码框与确认对话框就是你的反悔按钮，点取消即安全退出。

02

纯原生 API，不借外力

Linux 直读 efivarfs，Windows 走固件环境变量 API。每个字节都在 janus-core 里按 EFI_LOAD_OPTION 结构解析，UTF-16LE 描述符 lossy 容错。

工作原理

三个经典的坑，都替你踩过了

写 UEFI 变量的门槛不在 API，而在权限、编码与内核保护。janus 把这些全部封装在平台后端 crate 里，对外只暴露统一的 BootManager 接口。

  • BootOrder 决定展示顺序，缺失或损坏的条目自动跳过。
  • BIOS/Legacy 机器会在启动时被识别，并给出明确提示。
  • efivarfs 仅 root 可读的发行版上，命令自动提权重执行。
  • 20 个单元测试覆盖解析、编码与 efivarfs 模拟目录的写入路径。
托盘常驻

菜单跟着固件状态走

  • "重启并进入"与"仅下次启动"分开，避免误触立即重启。

自更新

更新前先验签，坏版本会自己回去

janus update 基于 shipup 构建：从签名清单检查新版本、下载安装包、逐层校验后原子替换二进制。伪造或被篡改的更新在进入安装流程前就会被拒绝。

  • 签名私钥只存在于 GitHub Secret 与维护者本机，永不入库。
  • 发布流水线签名后还会用内嵌公钥做一次复验，双重防呆。
  • 支持 file:// 本地清单与自定义端点，便于内网镜像与测试。
  • 自更新链路已在本机用签名清单完成端到端实测。

会改动我的默认引导顺序吗？

不会。Janus 只写入一次性的 BootNext 变量，BootOrder 保持不动；下一次启动走你选的系统，之后固件自动恢复原有顺序。

需要 root / 管理员权限吗？

写固件变量需要。Linux 上按动作经 pkexec 弹 polkit 密码框（托盘本身以普通用户运行）；Windows 在启动时经 UAC 提权一次，整个会话只弹一次。

支持 BIOS / Legacy 启动的机器吗？

不支持。Janus 启动时会检测 efivarfs（Linux）或固件变量接口（Windows），BIOS/Legacy 环境会得到明确提示。

自更新如何保证不被劫持？

更新清单用项目专属 Ed25519 密钥签名，公钥编译进二进制；下载包再做 SHA-256 与包签名校验。升级后连续两次启动失败会自动回滚到上一版本。

Linux 托盘图标不显示怎么办？

需要桌面环境支持 StatusNotifierItem：Ubuntu（自带 AppIndicator 扩展）与 KDE 默认满足；同时会话中需要有 polkit agent。
